# 모바일 청첩장

Vite + React로 만든 모바일 청첩장입니다. 정적 사이트로 빌드되며, RSVP·방명록은 구글 시트에 저장합니다 (무료, 사용하지 않아도 멈추지 않음).

## 구성

| 섹션 | 내용 |
| --- | --- |
| 커버 | 날짜, 메인 사진, 신랑·신부 이름, 일시·장소 |
| 인사말 | 초대 문구, 혼주 성함 |
| 예식 일시 | 달력, 실시간 카운트다운, D-day 문구 |
| 갤러리 | 3열 썸네일(9장 이후 더보기), 스와이프 가능한 전체화면 뷰어 |
| 오시는 길 | 지도(카카오맵, 키가 없으면 OpenStreetMap), 네이버지도·카카오맵·티맵 길찾기, 주소 복사, 교통편 |
| 참석 의사 전달 | 신랑/신부측, 참석 여부, 인원, 식사 여부 |
| 마음 전하실 곳 | 신랑측·신부측 계좌 접이식 목록, 복사 버튼, 카카오페이 링크(선택) |
| 방명록 | 작성·더보기·비밀번호로 삭제 |
| 공유 | 카카오톡 공유, 주소 복사 |
| 배경음악 | 우측 상단 재생/정지 버튼 |

## 시작하기

```bash
npm install
npm run dev      # http://localhost:5173 (같은 와이파이의 휴대폰에서도 접속 가능)
npm run build    # dist/ 에 정적 파일 생성
npm run preview  # 빌드 결과 미리보기
```

`.env` 없이도 `npm run dev`는 바로 실행됩니다. 이때 RSVP·방명록은 브라우저 localStorage에 저장되는 **로컬 모드**로 동작합니다. 배포 빌드에서는 로컬 모드를 쓰지 않으므로, 배포 전에 아래 구글 시트 설정을 꼭 해주세요 (설정이 빠지면 방명록에 오류가 표시됩니다).

## 디자인 템플릿

`wedding.js`의 `theme` 값이나 정보 입력 페이지의 **디자인 선택**에서 고릅니다.

| `theme` | 이름 | 특징 |
| --- | --- | --- |
| `minimal` | 미니멀 화이트 | 아치형 사진, 세리프 글꼴, 토프 색 |
| `floral` | 로맨틱 플로럴 | 액자형 사진과 모서리 꽃 장식, 필기체, 더스티 로즈 |
| `dark` | 모던 나이트 | 화면을 채운 사진 위 글자, 짙은 배경과 골드 포인트 |
| `modern` | 볼드 타이포 | 큰 날짜와 정사각 사진, 굵은 고딕, 테라코타 포인트 |

색·글꼴·섹션 제목 장식은 [src/styles/themes.css](src/styles/themes.css), 템플릿 목록과 표지 구성은 [src/themes/index.js](src/themes/index.js)에 있습니다. 새 템플릿을 추가하려면 `THEMES`에 항목을 넣고 `themes.css`에 `:root[data-theme='새 id']` 색 변수를 정의하면 됩니다. 표지 구성(`cover`)은 기존 `arch`·`frame`·`full`·`type` 중에서 고르거나 [Cover.jsx](src/components/Cover.jsx)에 새로 추가합니다.

## 정보 입력 페이지 (`/edit`)

코드를 몰라도 신랑·신부나 가족이 청첩장 정보를 채울 수 있는 페이지입니다. 배포 주소 뒤에 `/edit`을 붙여 열고, 개발 중에는 `http://localhost:5173/edit.html`로 엽니다. 하객용 페이지에는 링크가 없고 검색에도 노출되지 않습니다.

1. 처음 들어오면 안내 화면에서 **빈 양식**으로 시작하거나 **지금 청첩장 내용**을 불러와 시작합니다.
2. 디자인 → 호스트 → 혼주 → 예식 → 인사말 → 오시는 길 → 계좌 → 공유 순서로 입력합니다. 입력한 내용은 그 브라우저에 자동 저장되어, 나중에 다시 열어도 이어서 쓸 수 있습니다.
3. 미리보기(PC는 오른쪽, 휴대폰은 하단 버튼)에서 실제 청첩장 화면이 바로 바뀝니다. 미리보기에서는 방명록·참석 의사·공유가 전송되지 않습니다.
4. 마지막에 **wedding.js 내려받기**(또는 내용 복사)를 눌러 개발자에게 전달합니다.

**전달받은 파일 반영하기**: `src/config/wedding.js`를 받은 파일로 바꾸고 `npm run build`로 확인한 뒤 커밋·push 하면 됩니다. 사진(`cover.image`, `gallery`)은 이 파일이 아니라 `photos/` 폴더로 관리하므로 그대로 유지됩니다.

예식장 검색은 카카오 장소 검색을 씁니다. 카카오 디벨로퍼스에서 **카카오맵 사용 설정**이 꺼져 있으면 검색 대신 직접 입력 안내가 나옵니다.

## 내용 수정

모든 문구와 정보는 [src/config/wedding.js](src/config/wedding.js) 한 파일에서 수정합니다. 위의 정보 입력 페이지를 써도 되고, 이 파일을 직접 고쳐도 됩니다.

- **사진**: 원본 사진을 아래처럼 `photos/` 폴더에 넣고 `npm run photos`를 실행하세요. `npm run dev`·`npm run build` 때도 자동으로 실행됩니다.

  ```
  photos/
    cover.jpg          ← 커버 사진 (가로 1200px로 줄임)
    gallery/
      01_xxx.jpg       ← 갤러리, 파일 이름순 (긴 변 1600px + 480px 썸네일)
      02_xxx.jpg
  ```

  - 줄인 결과물은 `public/images/`에, 갤러리 목록은 `src/config/photos.generated.js`에 자동으로 만들어집니다. **이 둘을 커밋**하면 배포에 반영됩니다. 원본(`photos/`)은 git·Vercel에 올라가지 않습니다.
  - 촬영 위치(GPS) 같은 메타데이터는 지워지고, 세로·가로 회전은 자동으로 맞춰집니다.
  - 아이폰 HEIC 사진은 처리되지 않을 수 있으니 JPG로 내보내서 넣어주세요.
  - 사진을 다시 넣으면 바뀐 것만 새로 만듭니다. 지금 들어 있는 SVG는 자리표시용이며 실제 사진을 넣으면 지워집니다.
- **배경음악**: `public/audio/bgm.mp3`처럼 파일을 넣고 `bgm: 'audio/bgm.mp3'`로 지정합니다. 비워두면 버튼이 숨겨집니다. 모바일 브라우저는 자동재생을 막기 때문에 하객이 버튼을 눌러야 재생됩니다.
- **지도 좌표**: 카카오맵에서 장소를 검색한 뒤 우클릭 → "여기 좌표 보기"로 위도(`lat`)·경도(`lng`)를 확인할 수 있습니다.
- **공유 미리보기**: `share.image`(기본 `public/images/og.png`)가 카카오톡 공유 카드 이미지입니다. JPG/PNG, 5MB 이하, 가로 800px 이상을 권장하며 SVG는 표시되지 않습니다. `share.siteUrl`에는 배포 주소를 적어주세요. 주소를 카톡방에 직접 붙여넣었을 때의 미리보기에 쓰입니다.

색상·폰트는 [src/styles/global.css](src/styles/global.css) 상단의 CSS 변수에서 바꿀 수 있습니다.

## 구글 시트 설정 (RSVP·방명록)

참석 의사와 방명록은 내 구글 드라이브의 스프레드시트에 쌓입니다. 처음 한 번만 설정하면 됩니다.

> **개인 Gmail 계정 하나로만 로그인한 창**(시크릿 창 등)에서 진행하세요. 여러 계정에 동시에 로그인돼 있으면 Apps Script가 "요청한 문서를 액세스할 권한이 없습니다" 오류를 냅니다. 회사(Workspace) 계정은 관리자 정책 때문에 파일 생성이나 "모든 사용자" 공개 배포가 막혀 있을 수 있습니다.

1. [Google 스프레드시트](https://sheets.new)에서 새 시트를 만들고 이름을 정합니다 (예: `청첩장 응답`).
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 편집기의 `Code.gs` 내용을 모두 지우고 [google-apps-script/Code.gs](google-apps-script/Code.gs) 내용을 붙여넣은 뒤 저장합니다.
4. 위쪽 함수 선택에서 **setup**을 고르고 **실행**합니다.
   - 권한 요청이 나오면 내 구글 계정을 선택합니다. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다. 내가 만든 스크립트가 내 시트에 접근하는 것이라 괜찮습니다.
   - 시트에 `참석 의사`, `방명록` 탭이 생기면 성공입니다.
   - [script.google.com](https://script.google.com)에서 프로젝트를 따로 만든 경우에도 됩니다. 이때는 setup이 내 드라이브에 `청첩장 응답` 시트를 새로 만들고, 아래 **실행 로그**에 시트 주소를 알려줍니다.
5. 오른쪽 위 **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**을 고릅니다.
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
6. **배포**를 누르고 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해 `.env`와 Vercel 환경 변수에 넣습니다.

```
VITE_SHEETS_API_URL=https://script.google.com/macros/s/xxxxxxxx/exec
```

- **응답 확인**: `참석 의사` 탭에서 바로 볼 수 있고, 필터·합계로 인원을 집계하거나 가족과 시트를 공유하면 됩니다.
- **방명록 관리**: 이상한 글은 `방명록` 탭에서 그 줄을 지우면 청첩장에서도 사라집니다. 숨겨진 D~F열(id·salt·hash)은 하객이 비밀번호로 글을 지울 때 쓰이니 건드리지 마세요. 비밀번호 자체는 저장되지 않습니다.
- **Code.gs를 수정했다면**: **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**로 올리세요. "새 배포"를 다시 만들면 URL이 바뀌어 환경 변수도 바꿔야 합니다.

## 카카오 설정 (공유·지도)

1. [카카오 디벨로퍼스](https://developers.kakao.com/console/app)에서 앱을 만듭니다.
2. **앱 → 플랫폼 키 → JavaScript 키**를 복사해 `.env`의 `VITE_KAKAO_JS_KEY`에 넣습니다.
3. 같은 화면의 **JavaScript SDK 도메인**에 청첩장을 여는 주소를 등록합니다. SDK가 이 도메인에서만 동작합니다.
   - 개발용 `http://localhost:5173`, 휴대폰으로 테스트한다면 `http://192.168.x.x:5173`
   - 배포 주소 (예: `https://our-wedding.vercel.app`)
4. **앱 → 제품 링크 관리 → 웹 도메인**에 배포 주소를 등록합니다. 여기 등록되지 않으면 공유 메시지의 버튼을 눌러도 청첩장이 열리지 않습니다.
5. 지도를 쓰려면 **카카오맵** 사용 설정을 켭니다. 꺼져 있거나 키가 없으면 OpenStreetMap으로 대체됩니다.

카카오 서버가 공유 이미지를 직접 내려받기 때문에 `localhost`에서 공유하면 카드에 이미지가 빠집니다. 이미지까지 확인하려면 배포한 뒤 테스트하세요.

## 배포

`npm run build` 결과인 `dist/` 폴더를 정적 호스팅에 올리면 됩니다. 상대 경로로 빌드되므로 하위 경로에서도 동작합니다.

- **Vercel / Netlify**: 저장소를 연결하고 Build command `npm run build`, Output `dist`. 환경 변수 2개(`VITE_SHEETS_API_URL`, `VITE_KAKAO_JS_KEY`)를 대시보드에 등록합니다.
- **GitHub Pages**: Actions로 `dist/`를 배포합니다. 환경 변수는 저장소 Secrets로 넘겨주세요.

배포 후에는 카카오 디벨로퍼스에 실제 도메인을 꼭 추가하고, `share.siteUrl`도 실제 주소로 바꿔주세요.

- **Vercel 무료(Hobby) 플랜**: 커밋 작성자 이메일이 Vercel에 연결된 GitHub 계정의 이메일이어야 push 시 배포됩니다. 다르면 배포가 `BLOCKED` 상태로 멈춥니다.
- **검색 노출 차단**: 이름·계좌번호가 검색되지 않도록 `index.html`의 `robots` 메타 태그와 `vercel.json`의 `X-Robots-Tag` 헤더로 검색엔진 수집을 막아 두었습니다. `robots.txt`로 막지는 않았는데, 그러면 카카오톡·SNS 링크 미리보기까지 안 나오기 때문입니다.
